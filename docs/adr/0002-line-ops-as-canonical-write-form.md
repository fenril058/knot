# 0002: 行操作とページ version を書き込みの正規形式にする

- 状態: 承認済み（CRDT を正規形式にしない根拠は ADR 0008 により置換）
- 決定日: 2026-07-10（記録日: 2026-08-02）

ページ本文の変更は、コミットログ上で行の `insert`、`update`、`delete` として表現する。
コミットは基準にしたページ version を持ち、競合したクライアントは最新のページ状態へ手元の変更をリベースして再送する。

インポートは Cosense 由来の行 ID と時刻を保つため行を直接書くが、コミットログには等価な行操作を記録する。
行操作が正規形式であるという決定は、すべての実行経路が同じ関数を通ることを意味しない。

## 却下した案

**ページ全文の置き換えを正規形式にする案**。
他者が変更した行まで古い本文で上書きするため採用しない。

**CRDT を最初から正規形式にする案**。
リアルタイム共同編集を得られる一方、真のデータが CRDT の内部表現になり、SQLite の行を直接読める透明性を失う。
2〜5 人の利用では競合がまれで、複雑さに見合わない。

## 帰結

- ページ version の競合とタイトルの衝突は別の競合であり、リベースで解けるのは前者だけである。
- コミットの再送は `commitId` で識別し、同じ ID で内容が異なる要求は拒否する。
- ページ削除も全行を削除するコミットとして記録し、本文の履歴を残す。
- リアルタイム共同編集を追加する場合も、DB の書き込み形式は変えず、編集画面で行 ID を逐次追跡する。
