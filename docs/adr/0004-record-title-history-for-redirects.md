# 0004: 旧タイトルからのリダイレクトのために title_history を今から記録する

- 状態: 承認済み
- 決定日: 2026-07-10（記録日: 2026-08-02）

`title_history` は、タイトルが変わるたびに旧タイトルとその有効期間（`started`、`ended`）を追記するテーブルである。
v1 にはこれを読む UI が無い（内部では次の `started` を決めるために `MAX(ended)` を引いている）。

それでも最初から記録するのは、旧タイトルからのリダイレクトを引くための索引だからである。
`commits.ops` には全コミットの行操作が残るので、原理的にはコミット列を再生すれば過去のタイトルは復元できる。
しかしリダイレクトは「存在しないタイトルへのアクセス」ごとに引くもので、そのたびにページの全履歴を再生するのは現実的でない。
`title_history` は、この参照を 1 クエリで済ませるための導出済みの索引である。

`page_visits` は将来のために置いているテーブルではない。
v1 でもテロメアの未読判定に読んでいる。

## なぜ素朴な履歴引きでは足りないか

タイトル行の編集は逐次保存される。
そのため「カレー」を「curry」へ変える途中の「カレ」「カ」「c」「cu」といった一時タイトルが履歴に残り、「カ」へのアクセスが curry へ転送されてしまう。
Cosense がアクセス履歴方式を採っているのはこの理由による。

`title_history` は有効期間（`started`、`ended`）を持つので、「一定時間以上そのページのタイトルであり続けたタイトル」だけを対象にする方針を第一候補とする。
編集途中の一時タイトルは数秒しか存続しないため、この条件で外れる。

精度が足りなければ、Cosense と同じアクセス履歴方式への切り替えを検討できる。
ただし現在の `page_visits` は `(user_id, page_id)` を主キーとし、最後の閲覧しか保持しない。
「そのタイトルであった期間に実際に閲覧された」を判定するには閲覧履歴を残す形へスキーマを変える必要があり、この代替案は無償では選べない。

どちらの方式でも、差し込み点は v1 の 404 ハンドラ（新規作成を促す画面）ひとつである。
