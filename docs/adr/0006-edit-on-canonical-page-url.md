# 0006: 正規 URL の SSR 本文を同じ場所で編集可能にする

- 状態: 承認済み
- 決定日: 2026-08-09
- 置換対象: ADR 0001 のうち、閲覧画面と編集画面を分離する決定

ページの正規 URL を `/:project/:title` とし、認証済み利用者はページ遷移せず同じ本文領域で編集する。
サーバサイドレンダリングによる初期表示を維持し、JavaScript が動かない場合と未ログインの場合も本文を閲覧可能にする。
既存の `/:project/:title/edit` は保存済みリンクとの互換性のため正規 URL へリダイレクトする。

実装は二段階に分ける。
第1段階では現在の全文 CodeMirror を再利用し、サーバサイドレンダリングされた本文領域を JavaScript で編集可能にする。
第2段階では、編集中の行に Cosense 記法を表示し、それ以外の行を整形表示する一行単位の WYSIWYG 的直接編集へ移行する。

第2段階へ入る前に、外部パーサを利用箇所から隔離する内部 API を設け、構文要素のソース範囲を取得可能にする。
これは parser の完全置換を決めるものではなく、issue #17 の着手条件の一部だけを先行させる。

TypeScript、Hono、SQLite、単一プロセスという ADR 0001 の決定は維持する。
閲覧可能な初期 HTML をサーバから返す決定も維持し、SPA 化は前提にしない。

## 却下した案

**閲覧画面と `/edit` の編集画面を分けたままにする案**。
既存実装を維持できるが、ページを開いた場所で直接編集する Cosense の中心的な操作と一致しないため採用しない。

**最初に SPA へ移行する案**。
クライアントの状態管理を一元化できる一方、JavaScript がない場合の閲覧性を失い、直接編集に不要なルーティングとデータ取得の変更まで同時に抱えるため採用しない。

**ルート統合と一行単位のエディタへの移行を一度に行う案**。
完成形へ早く到達できる一方、URL、保存、選択、IME、undo/redo、表示切り替えの変更が一体化し、不具合の原因と回帰範囲を分離できないため採用しない。

## 帰結

- 第1段階でも正規 URL から編集と保存を完結させ、閲覧画面と編集画面の分離を解消する。
- 第2段階では、行の選択変更だけで本文データを変更せず、コピー、複数行選択、貼り付け、IME、undo/redo を維持する必要がある。
- リンクを開く操作と、その行へカーソルを置く操作を区別する必要がある。
- 現在のコミット、version 競合時のリベース、未送信変更の復元、テロメア、CSP の性質を両段階で維持する必要がある。
- 新規ページ、未ログイン、JavaScript 無効、ネットワーク失敗、400 応答、version 競合を E2E テストの回帰対象にする。
- issue #22 のインデント表示は、第2段階の行表示へ組み込む。
