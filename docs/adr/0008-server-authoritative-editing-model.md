# 0008: サーバを正準状態とする編集モデルを採る

- 状態: 承認済み（ADR 0002 の CRDT を正準形式にしない根拠を置換）
- 決定日: 2026-08-23

knot はブラウザからの利用を主要な編集経路とし、サーバが永続化層（現在は SQLite）に保持するページを正準状態とする。
クライアントは `baseVersion` に対する変更を送り、サーバは受理したコミットによってページ version を進める。

version 競合が起きた場合は、基準にしたページ、手元の変更、サーバ上の最新版を比較する。
異なる行への変更はリベースし、同一行の異なる変更など、両方の意図を保ったまま適用できない変更は明示的な競合として利用者が解消する。

ローカル同期は長文編集を補助する経路とし、ブラウザやローカル環境を対等な独立 replica にはしない。
スマートフォンを含むブラウザから、サーバへ接続できる状態でいつでも編集できることを優先する。

## 却下した案

**CRDT を永続化の正準形式にする案**。
同時編集やオフライン編集の自動収束には適するが、CRDT を永続化の正準形式にする場合は、収束に必要な CRDT 固有の状態を正準状態として継続的に保持する必要がある。
knot が優先する編集経路では、サーバがコミットを直列化でき、意図が衝突する変更の手動解消も許容できるため採用しない。

CRDT の要否を利用人数だけでは判断しない。
利用人数が少なくても独立 replica 間の自動収束が必要なら CRDT を検討する理由になり、利用人数が増えてもサーバを介した編集で要件を満たせるなら採用理由にはならない。

**ローカル環境を完全な local-first replica にする案**。
長時間のオフライン編集や複数コミットの蓄積を第一級の機能にすると、サーバ上の最新版との同期と競合解消を製品機能として設計する必要がある。
knot はローカル同期を補助経路に限定し、競合時の手動解消を許容するため採用しない。

## CRDT を再検討する条件

次のいずれかが製品要件になった場合は、CRDT を含む同期方式を再検討する。
CRDT を将来にわたって採用しないと決めるものではない。

- 長時間のオフライン編集を第一級の機能にする。
- PC とスマートフォンのブラウザ、ローカルエディタを対等な独立 replica にする。
- サーバへ接続する前に複数のコミットを積み、接続後に自動収束させる。
- 複数の knot サーバ間または peer-to-peer で同期する。
- 中央の sequencer なしで編集する。
- 同一行の並行編集を、手動の競合解消なしで統合することを主要な要件にする。

利用人数の増加だけでは再検討しない。
同一ページの同時編集密度と、独立 replica を必要とする編集経路を判断材料にする。

## 帰結

- CRDT の内部状態を永続化の正準形式にしない。
- vector clock や Lamport clock などの metadata を将来用として行操作へ追加しない。
- realtime collaboration を追加する場合も、編集画面の同期機構と DB の正準形式を分離する。
- ローカル同期で自動的にリベースできない変更は、手元の内容を保持して利用者の解消を待つ。
