# 0009: 同一行の競合を明示し、並行挿入は先に受理した行を先にする

- 状態: 承認済み
- 決定日: 2026-08-23

リベースでは、基準にした行を手元とサーバ上の最新版が異なる内容へ変更した場合を競合とする。
片方が行を更新し、もう片方が削除した場合も競合に含める。
競合時は手元の内容を編集画面に保持して自動送信を止め、基準、手元、サーバ上の最新版を利用者へ示したうえで、明示的な操作によって保存を再開する。
競合解消中の草稿もブラウザへ永続化し、再読み込み後は自動送信せずに解消待ちを再開する。

タイトルが並行して変更された場合も同じページを追跡する方法は ADR 0010 に従う。

同じ行の直後へ手元とサーバ上の最新版がそれぞれ行を挿入した場合は、サーバが先に受理した行を先にし、リベースする手元の行を後に置く。
各クライアント内の行順は維持する。

## 却下した案

**競合した行を手元の内容で無言で上書きする案**。
サーバが先に受理した利用者の変更を失い、両方の意図を保てないため採用しない。

**リベースする手元の挿入を先に置く案**。
後から保存した利用者の行が先に受理された行の前へ回り込み、サーバが確定した順序を不必要に逆転するため採用しない。

**行 ID 順に並べる案**。
行 ID は同じクライアントが連続して追加した行の順序を表す値ではなく、利用者が作った行順を変えうるため採用しない。

## 帰結

- 手元だけ、またはサーバ上の最新版だけが変更した行は自動的にリベースする。
- 手元とサーバ上の最新版が同じ内容へ変更した行は競合にしない。
- 基準にない同じ行 ID を手元とサーバ上の最新版が異なる内容で挿入した場合も競合にする。
- 同じ本文の行が複数あり、手元で削除した行を本文だけでは識別できない場合は、サーバ上で更新された同文行との競合として扱う。
- 競合解消中の内容は、自動保存の対象にしない。
- 競合解消中の草稿は、再読み込みに備えてブラウザへ保存する。
- タイトルが並行して変更されても、既存ページの編集はページ ID によって version 競合として扱う。
- 同じ挿入 anchor に対する順序は、先にサーバが受理した側、リベースする側の順になる。
