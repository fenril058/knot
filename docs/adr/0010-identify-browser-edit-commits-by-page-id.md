# 0010: ブラウザ編集コミットの対象をページ ID で識別する

- 状態: 承認済み
- 決定日: 2026-08-23

既存ページのブラウザ編集では、ページ ID を書き込み対象の識別子とする。
タイトルはページ ID を送らない既存クライアントとの互換経路と、新規ページの作成時に使う。

ページ取得 API は任意の `pageId` queryを受け取り、指定された場合は URL のタイトルではなくページ ID から現在のスナップショットを返す。
編集コミット API は request の任意 `pageId` を同様に優先し、成功 response へ `pageId` を含める。
サーバは指定されたページが URL のプロジェクトに属することを検査する。

これにより、ページ表示後またはコミット送信後に別の利用者がタイトルを変更しても、ブラウザは同じページを追跡して version 競合を処理できる。
新規ページも最初の成功 response からページ ID を取得し、後続コミットでは同じ識別方法へ移る。
既存ページのブラウザ内の回復記録もページ ID をキーにし、別セッションでタイトルが変更されても同じ草稿を参照する。

## 却下した案

**URL のタイトルだけで対象ページを識別し続ける案**。
並行してタイトルが変更されると古い URL はページを解決できず、version 競合に必要な最新版を返せないため採用しない。

**ページ ID だけの新しい書き込み URL に置き換える案**。
既存クライアントとの互換性を壊し、新規作成ではまだページ ID が存在しないため採用しない。

## 帰結

- ページ取得 API の `pageId` queryと、編集コミット API の request / response に `pageId` を追加する。
- `pageId` を送らない既存クライアントのタイトル経路は維持する。
- コミットログと `LineOp` の正規形式は変更しない。
- 適用済みコミットの冪等な再送は、対象ページが削除済みでもストレージのコミット記録で判定する。
- タイトルをキーにした既存の回復記録は読み取り時にページ ID のキーへ移す。
- ページ作成前にタイトルをキーとして保存した回復記録も、作成後の初回読み取りでページ ID のキーへ移す。
