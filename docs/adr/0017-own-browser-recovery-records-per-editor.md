# 0017: ブラウザの回復記録を編集画面ごとに分離する

- 状態: 承認済み
- 決定日: 2026-09-18

同じページを複数タブで編集できるよう、ブラウザの回復記録はページ ID と編集画面 ID の組で区別する。
各編集画面は自分の回復記録だけを更新・削除し、別タブの保存成功で未保存の内容を失わないようにする。
ADR 0010 のページ ID は編集対象の識別子として維持し、編集画面 ID は回復記録の所有者を区別する。

回復記録はタブを閉じても残る `localStorage` に保存し、同じタブでの再読み込みや履歴移動では `sessionStorage` の参照から自分の記録を復元する。
通常のページ遷移では記録を自動選択せず、残っている記録を明示的に選べるようにする。
`sessionStorage` は新しいタブへ複製される場合があり、通常のページ遷移で参照を無条件に再利用すると、別タブが同じ記録を所有してしまうためである。
同じタブで通常のページ遷移をして戻った場合も手動選択になることを受け入れる。
選んだ記録は新しい編集画面のキーへコピーし、元の記録を変更しない。

## 却下した案

**同じページの編集画面を排他する案**。
複数タブでの編集を維持する要件に合わないため採用しない。

**回復記録を `sessionStorage` だけに保存する案**。
タブを閉じた後に未保存の内容を復元できなくなるため採用しない。

**通常のページ遷移でも `sessionStorage` の参照を無条件に再利用する案**。
新しいタブへ複製された参照から他タブの記録を自動復元し、双方が同じキーを更新・削除しうるため採用しない。

**`BroadcastChannel` や Web Locks で存続中の編集画面を検出する案**。
通常遷移で自動復元するために生存確認と通信失敗時の処理を加える必要があり、明示的な選択で安全に復元できるため採用しない。

## 帰結

- 従来のページ ID キーとタイトルキーにある回復記録は、編集開始時に現在の編集画面のキーへ移す。
- 同じページに複数の記録があっても、参照のない編集画面はどれも自動復元しない。
- コピー元が閉じたタブの記録だった場合も、その記録は候補に残る。
  不要になった候補の整理は issue #169 で扱う。
