# 0018: 本文を tab order に載せず、ショートカットでエディタにフォーカスする

- 状態: 承認済み
- 決定日: 2026-09-18

SSR 本文の行を click / tap すると編集が始まる（ADR 0006 の直接編集）。
そのキーボードでの対応物を、`ctrl(cmd) + e` でエディタにフォーカスし、`Escape` でフォーカスから抜ける形で提供する。
`.line-row` と `#editor-root` に `tabindex` は与えず、本文は tab order に載せない。

エディタを Tab でフォーカスできるようにすると、次の Tab が「次の要素へのフォーカス移動」ではなく「タブ文字の入力」になり、本文より後ろにある UI へ到達できなくなる。
Cosense は同じ理由で Tab 方式を採らず、`ctrl(cmd) + g`（検索フォーム）、`ctrl(cmd) + e`（エディタ）、`Escape`（フォーカスから抜ける）というショートカットでフォーカスを移す設計にしている。
knot もこれに合わせる。

Cosense では、一度もクリックしていない状態からキーボードだけで編集を開始することはできず、未実装の要望として残っている。
knot は編集開始の状態を Editor bootstrap が持つため、まだ編集を開始していない SSR 表示直後からも `ctrl(cmd) + e` で開始できる。
ここは Cosense の制約を模倣しない。

行を指していない起動では最終行に caret を置く。
先頭行はタイトル行であり、そこに caret を置くと、そのまま入力した利用者が意図せずページをリネームする。

## 却下した案

**`#editor-root` または `.line-row` に `tabindex` を与える案**。
Tab でエディタに入れる代わりに、以降の Tab がタブ文字の入力になり本文より後ろの UI へ到達できなくなる。
`.line-row` 単位にすると行数分の tab stop ができ、roving tabindex の設計も要る。

**「編集」ボタンを操作メニューに戻す案**。
キーボード到達性は最小の変更で回復するが、issue #175 と ADR 0006 が外そうとしている編集と閲覧のモード切り替えを副経路として復活させるため採用しない。

**キーボード経路を別 issue に分離する案**。
「編集」ボタンの削除がキーボードでの編集開始経路を失わせた変更そのものであり、同じ変更で塞ぐ。

## 帰結

- 本文は Tab では到達できない。`ctrl(cmd) + e` を知らない利用者は、キーボードだけでは編集を開始できない。
- `Escape` はエディタから抜ける唯一の経路になる。
  補完の `Escape` は `Prec.highest` で先に処理され、選択の `simplifySelection` も先に試されるため、blur はそのどちらにも該当しないときだけ働く順序に置く。
- macOS の `ctrl + e`（行末移動）は、エディタ内では従来どおり働く。
- `ctrl(cmd) + g` など Cosense の他のショートカットは、この決定では扱わない。
