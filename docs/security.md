# セキュリティ

knot の変更時に維持する安全要件を示します。
現在のアクセス境界を選んだ理由は [ADR 0005](adr/0005-closed-wiki-access-boundary.md) を参照してください。

## 認証と認可

ログイン、静的アセット以外のルートは、セッションまたは personal access token による認証を要求します。
HTML ルートはセッションだけを受け付け、API と添付ファイルはセッションまたは personal access token を受け付けます。

ブラウザのセッション ID は `connect.sid` cookie に保存します。
cookie には `HttpOnly`、`SameSite=Lax`、設定に応じた `Secure` を付けます。
セッションの有効期限は既定で 30 日とし、利用中は延長します。

cookie 認証を使う書き込み API は `X-Knot-Client` ヘッダも要求します。
このヘッダと `SameSite=Lax` を CSRF 防御の境界として保ちます。

ログイン試行は接続元とユーザー名の組み合わせで制限します。
リバースプロキシ配下で接続元を判定する際の制約は [運用文書](ops.md#3-リバースプロキシ) を参照してください。

## HTML と外部コンテンツ

利用者の入力を HTML に変換するときは、テキストノードと HTML 属性値をエスケープします。
リンク、画像、動画、音声は許可した URL スキームだけを扱います。
iframe は設定で許可したホストに限って生成します。

Content Security Policy は、エスケープや URL 検証が破られた場合の被害を抑える追加の防御です。
CSP を出力時の安全化の代わりにしません。

## 添付ファイル

アップロードサイズを設定値以下に制限します。
対応しているファイル形式では、申告された Content-Type とマジックバイトが一致することを検査します。

安全にインライン表示できると定めた形式だけをインラインで配信します。
HTML、SVG、その他の許可していない形式は `Content-Disposition: attachment` を付けます。
すべての応答に `X-Content-Type-Options: nosniff` を付けます。

アップロード処理がボディ全体をメモリに載せる現在の制約は、ログイン済み利用者だけがアップロードできることを前提に受け入れています。
公開アップロードを追加する前に、ストリーミング処理とリソース制限を設計してください。

## 回帰テスト

セキュリティヘッダの存在だけでなく、悪意ある入力が実行可能な HTML にならないことをテストします。
認証範囲、CSRF ヘッダ、URL スキーム、iframe の許可ホスト、添付のマジックバイトと配信方法を回帰テストの対象にします。
