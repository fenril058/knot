**Architecture:** サーバは従来どおり type stripping のみでビルドしない。

`src/core/` の `diffLines` / `rebase` / `applyOps` / `ulid` / `pageHref` をバンドルに同梱してサーバとコードを共有する（設計書「行差分は core の純粋モジュールをバンドルに同梱し、サーバ側処理とコードを共有する」の実現）。

**Tech Stack:** CodeMirror 6（`@codemirror/state` / `@codemirror/view` / `@codemirror/commands` / `@codemirror/autocomplete`）、`@progfay/scrapbox-parser`（既存依存）、Rolldown 1.x、oxlint、`@playwright/test`。

**設計書からの改訂:** 設計書とロードマップはクライアントバンドラとして esbuild を挙げているが、本計画では Rolldown 1.x を採用する（2026-07-16 のユーザー決定）。
理由: Rolldown 1.0 は 2026-05 に安定版となり API が固定され、esbuild と同等の機能を「1 エントリ → 1 出力」の同程度の設定量で提供する。
Vite 8 以降のエコシステムの重心が Rolldown / Oxc ツールチェーンへ移っており、同時に導入する oxlint と同一ファミリーで揃う。
フル Vite は不採用とする。knot の HTML は hono がSSR するため、Vite の dev サーバ・HMR・index.html 変換を使う場所がなく、バックエンド統合（manifest 経由のアセット解決）の複雑さだけが残るためである。

## Global Constraints

- Node.js >= 24。サーバコードは type stripping のみでビルドしない。クライアントバンドルだけが Rolldown を使う。
- import の方向: `src/client/` からは `src/core/` のみ import できる。`src/client/` → `src/server/` / `src/storage/` の import は禁止。サーバコードから `src/client/` を import することも禁止。
- バンドル出力は `public/build/`（gitignore）。HTML からは `<script type="module" src="/assets/build/<name>.js">` で読み込む。module script では `document.currentScript` が null のため、サーバ→クライアントのデータ受け渡しは**コンテナ要素の data-\* 属性 + API fetch のみ**とする（インライン JSON 埋め込み禁止）。
- CSP: インライン `<script>`・`<style>`・`on*=` 属性は引き続き全面禁止。唯一の例外として、**編集画面の応答のみ** `style-src 'self' 'nonce-<per-request>'` を既存 CSP に追記し、CodeMirror（style-mod）が動的注入する `<style>` タグを nonce で許可する。他ルートの CSP は 1 バイトも変えない。
- `/api/knot/*` への POST/PUT/DELETE は必ず `X-Knot-Client` ヘッダを付ける。
- コミット契約: 送信中コミットはページごとに同時 1 件。**リベース後の再送は新しい commitId**、**同一内容の再送（ネットワーク失敗・リロード後）は同じ commitId**（`ops_hash` の冪等性に依存）。
- 各コミット前に `direnv exec . npm test`、`direnv exec . npx tsc --noEmit`、`direnv exec . npm run lint`、`direnv exec . npm run build:client` をすべて通す（Task 3 以降）。
- 依存を追加したら `npm install` で package-lock.json を更新し、nix（importNpmLock）の dev shell を `direnv reload` で再構築してから作業を続ける。
- Playwright のテストは `e2e/` ディレクトリの `*.spec.ts` に置き、`node --test 'test/**/*.test.ts'` の glob と交差させない。テストは仕様どおり **1 本だけ**。
- 純ロジック（sync / highlight / smartPaste / match / indent / duplicateOps / completeContext）は CodeMirror 非依存モジュールに置き、`test/client/` などの node --test 配下でテストする。
- 既存ヘルパを再実装しない: `diffLines` / `rebase` / `applyOps` / `validateOps` / `ulid` / `titleLc` / `pageHref` / `resolveProject` / `resolvePage` / `jsonError` / `pageToJson` / `makeServer` / `seedPage`。
- タイムスタンプは Unix 秒、ID は ULID。

**npm scripts（追加）:** `build:client`（`rolldown -c`）、`watch:client`（`rolldown -c --watch`）、`lint`（Task 3 時点では `oxlint src public test`。`e2e` は Task 14 でディレクトリ作成と同時に対象へ追加する）、`test:e2e`（`playwright test`、Task 14）。

**依存（追加）:** dependencies に `@codemirror/state` / `@codemirror/view` / `@codemirror/commands` / `@codemirror/autocomplete`。devDependencies に `rolldown`（1.x）、`oxlint`（最新）、`@playwright/test`（Task 14）。

- `src/core/id.ts` の browser 非互換要素は `node:crypto.randomBytes` の 1 箇所だけ。`globalThis.crypto.getRandomValues` へ置換すれば isomorphic になる（API・出力形式は不変）。
- CSP は `src/server/app.ts` の `cspValue()` + after-next ミドルウェアで全応答に固定文字列を付けている。style-src は未指定（= default-src 'self' にフォールバックし、インライン `<style>` はブロックされる）。

- 409 応答は `{error: 'conflict', reason, page: {id, title, version, created, updated, lines: [{id, text, userId, created, updated}]}}`（`src/server/http.ts` の `pageToJson`）。行に `updatedVersion` は**含まれない**。core の `rebase` は行の id と text しか参照しないため、リベースには影響しない（テロメア表示の精度にのみ影響し、`page.version` を充当して許容する）。
- `public/search.js` のタイトル一致は `.includes()` の substring であり、fuzzy 化は plan-04 が本計画に明示的に先送りしたもの。`pageHref` を「keep in sync」コメント付きで手動複製している。
- flake.nix は `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` と `PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/ms-playwright"` を設定済み。ブラウザバイナリは `npx playwright install chromium` で導入する。
- `Storage.getUserById(id): Promise<AuthUser | null>`（`AuthUser.name` / `.displayName` あり）、セッションミドルウェアは `c.set('userId', ...)`（`ApiEnv.Variables.userId`）。
- 閲覧画面のテロメア規約: `.telomere` + `unread` + `age-1..3` クラス、`data-updated` / `data-user` 属性（`src/server/views/pageView.ts`、`public/app.css`）。

**スコープ判断（本計画での追加判断）:**

### Task 2: core — fuzzy マッチャ `src/core/match.ts`

**目的:** タイトル検索とエディタ補完で共有するマッチャ（設計書「検索 UI」の fzf 相当。plan-04 からの先送り分）。

**Files:**
- Create: `src/core/match.ts`
- Test: `test/core/match.test.ts`

**Interfaces:**
```ts
export function normalizeForMatch(s: string): string;
// lowercase + カタカナ（U+30A1〜U+30F6）→ ひらがな

export function fuzzyScore(query: string, candidate: string): number | null;
// 部分列不一致は null。スコアが大きいほど良い一致

export function rankTitles<T>(
  query: string,
  items: readonly T[],
  getText: (item: T) => string,
  limit?: number,
): T[];
```

**挙動仕様:**
- クエリは空白で分割し、全語が（正規化後の）候補に部分列一致したときだけ採用する（語順不問）。
- スコアは連続一致ボーナス + 先頭・語境界一致ボーナス + 候補が短いほど加点。合計で順位付けする。
- 同点は候補文字列の辞書順で安定させる（順位の決定性）。
- 空クエリは全件を元の順で返す。
- `rankTitles` は `limit` 件（既定 20）で打ち切る。

- 完全不一致は null（`fuzzyScore('xyz', 'Scrapbox')`）。
- かなカナ同一視: `かたかな` が `カタカナ` に一致する。

### Task 4: client 純ロジック — 自動保存の 3 状態機械 `sync.ts`

**目的:** 設計書「エディタ」の核心（確認済みスナップショット / 送信中コミット / 未送信編集、409 リベース、リロード再送）を CodeMirror なしで完全にテストする。

**Files:**
- Create: `src/client/editor/sync.ts`
- Test: `test/client/sync.test.ts`

**Interfaces:**
```ts
import type { Line, LineOp } from '../../core/ops.ts';

export type Snapshot = { version: number; lines: Line[] };

export type PendingRecord = {
  commitId: string;
  baseVersion: number;
  ops: LineOp[];
  baseLines: Line[];
  title: string;
};

export type SyncEffect =
  | { type: 'send'; commit: { commitId: string; baseVersion: number; ops: LineOp[] }; title: string }
  | { type: 'persist'; record: PendingRecord | null }  // null = 永続化のクリア
  | { type: 'schedule' };                              // 500ms 後に flush() を呼べ（タイマー実体は配線側）

export class SyncEngine {
  constructor(init: {
    snapshot: Snapshot;
    title: string;
    userId: string;
    isNew: boolean;
    makeId?: () => string;   // テストで決定的に注入
    now?: () => number;
  });
  bufferChanged(texts: string[]): SyncEffect[];
  flush(): SyncEffect[];
  ackSuccess(version: number): SyncEffect[];
  ackConflict(latest: { version: number; title: string; lines: Line[] }): SyncEffect[];
  ackFailure(): SyncEffect[];
  readonly status: 'saved' | 'saving' | 'dirty' | 'error';
  readonly currentTitle: string;
  readonly confirmedLines: readonly Line[];  // テロメア gutter 用
}

export function lineMeta(
  confirmed: readonly Line[],
  bufferTexts: readonly string[],
  self: { userId: string; now: number },
): { updated: number; userId: string; updatedVersion: number }[];
// alignLines ベース。keep 行は元メタ、add（未保存）行は self のメタ + updatedVersion は Number.MAX_SAFE_INTEGER

export function serializePendingRecord(record: PendingRecord): string;
export function parsePendingRecord(raw: string): PendingRecord | null;  // 形が不正なら null
```

**挙動仕様:**
- `bufferChanged`: バッファを記録し、inflight がなければ `schedule` を返す（debounce の起点）。status は 'dirty'。
- `flush`: inflight があれば何もしない（**ページごと同時 1 件**の制限）。なければ `diffLines(confirmed.lines, buffer, makeId)` を取り、ops が空なら何もしない。非空なら commitId を採番して inflight にし、`send` + `persist` を返す。inflight には `expectedLines = applyOps(confirmed.lines, ops, ctx)` を保持する。
- `ackSuccess(version)`: `confirmed ← { version, lines: expectedLines }`、inflight 解除、`persist(null)`。バッファとの差分がまだあれば続けて次のコミットを生成してよい（effects に次の `send` + `persist` を含める）。
- `ackConflict(latest)`: 設計書「リベース」に従い、**送信中と未送信の両方を含む手元状態**を `local = applyOps(confirmed.lines, diffLines(confirmed.lines, buffer, makeId), ctx)` として作り、`ops' = rebase(confirmed.lines, local, latest.lines)` を計算する。`confirmed ← latest` とし、ops' が非空なら**新しい commitId** で `send` + `persist`。`currentTitle ← latest.title`。このとき失効した inflight の行 ID は再利用せず新しい ID を採番する（`rebase` の前提「local にしか無い ID は latest に存在しない」を保つ）。
- `ackFailure()`: ネットワーク断・5xx。inflight を**保持したまま** `schedule` を返す（次の flush では同一内容なので**同じ commitId** で再送 = 冪等）。status は 'error'（復帰可能）。配線側が送信自体を断念した場合（keepalive の 64KB 超過等）も `ackFailure()` を呼び、inflight が応答待ちのまま宙に浮かないようにする。
- 新規ページ（`isNew: true`）: `snapshot` は `{ version: 0, lines: [] }` を渡し、初期バッファは `[title]` 1 行とする。**ユーザーの編集イベント（bufferChanged）が一度も来ないうちは flush しても send しない**（開いただけでページが作られるのを防ぐ）。最初のコミットは baseVersion 0 で、先頭 op がタイトル行の insert になる（`diffLines([], buffer)` の自然な結果）。
- タイトル追跡: 確認済み先頭行のテキストが変わったら `currentTitle` を更新する（以後の `send` effect の `title` が変わり、配線側が commit 先 URL を追従させる）。

**目的:** Task 4 の状態機械を CodeMirror・fetch・タイマー・localStorage・DOM につなぎ、「開いて書けば保存される」を成立させる（ハイライト等は後続タスク）。

**Interfaces:**
```ts

import type { Line, LineOp } from '../../core/ops.ts';
import type { Snapshot } from './sync.ts';

export function fetchPage(project: string, title: string):
  Promise<{ title: string; snapshot: Snapshot } | null>;  // 404 → null（新規モード）

export function postCommit(
  project: string,
  title: string,
  commit: { commitId: string; baseVersion: number; ops: LineOp[] },
  opts?: { keepalive?: boolean },
): Promise<
  | { kind: 'ok'; version: number }
  | { kind: 'conflict'; page: { version: number; title: string; lines: Line[] } }
  | { kind: 'bad'; message: string }
  | { kind: 'network' }
>;
```

**挙動仕様:**
- 409 応答の行 JSON には `updatedVersion` がないため、api.ts のアダプタで `page.version` を充当して `Line[]` 化する（rebase は id / text しか使わないため正しさに影響しない。テロメア精度のみ粗くなる — 許容）。
- 起動順:
  1. `#editor-root` の dataset を読む。
  2. localStorage（キー: `knot:pending:<project>/<titleLc>`）に PendingRecord があれば**同じ commitId で先に再送**する。ok / bad ならレコードをクリア。conflict なら `{ version: record.baseVersion, lines: record.baseLines }` を snapshot として engine を初期化し、ackConflict 経路で解決する。
  3. `fetchPage`。null なら新規モード（初期バッファはタイトル行 1 行）。
  4. EditorView を構築する。`EditorView.cspNonce` facet に `data-csp-nonce` を渡す。extensions は history + defaultKeymap の安全なサブセット + updateListener。
- updateListener の docChanged → `engine.bufferChanged(行テキスト配列)` → schedule effect を 500ms debounce タイマーへ → 満了で `engine.flush()` → send effect を `postCommit` へ。effects の executor は send / persist / schedule を種別ごとに逐次処理する 1 箇所の関数にする。
- `pagehide` と `visibilitychange`（hidden）: 即 flush し、send を `keepalive: true` で送る。keepalive fetch は本文約 64KB の制限があるため、超過時は送信せず `engine.ackFailure()` を呼んで localStorage の永続化に委ねる（設計書「保存完了を保証しない」の範囲内。inflight を応答待ちのまま残さない）。

| keepalive 送信 | `fetch(..., {keepalive:true})` 同一オリジン | default-src 'self' |
| テロメア gutter / ダイアログ / メニュー | 静的 app.css + `<dialog>` | インラインスタイル・ハンドラなし（Task 9/13 のサーバテストで on\*= 不在を固定） |
| 検索・page-menu バンドル | `/assets/build/*.js` | default-src 'self'。閲覧・一覧の CSP は不変（Task 7 のテストで固定） |

**純ロジックのテスト所在:** sync（Task 4）、highlight（Task 5）、smartPaste（Task 6）、match（Task 2）、completeContext（Task 10）、indent（Task 11）、duplicateOps（Task 13）、alignLines（Task 1）— すべて `node --test` 配下。CodeMirror に触るのは `cm/` 配下と main.ts のみで、その回帰は Playwright 1 本（Task 14）と手動確認が担う。

**plan-04 errata の教訓の適用:** コピー用実装コードなし（インターフェース + 挙動 + テスト仕様のみ）/ CSP クロスチェック表を本節に置いた / spec-ambiguity-audit を実施済み（下記）。

**spec-ambiguity-audit の実施記録（2026-07-16、作成時）:** 低文脈モデルのコールドリードで 32 件の疑問点を抽出し、機械フィルタで 8 件を有効と判定して本書に反映済み。
反映内容: isomorphic 化の要件範囲の明記（Task 1）、新規モードの初期 snapshot と起動時再送 409 の初期化 version の明記（Task 4/8）、fail-soft 時のオフセット基準の明記（Task 5）、keepalive 断念時の `ackFailure()` 遷移（Task 4/8）、`PasteContext.from/to` の単位（Task 6）、hash 補完の置換条件を空白判定に確定（Task 10）、lint 対象への `e2e` の追加タイミング（Task 3/14）。

## オープンリスクと解決方針

1. **CodeMirror × CSP（最重要）**: style-mod は document へ `<style>` を注入するため、現行 CSP では確実にブロックされる。解決は編集画面限定の per-request nonce（Task 7）+ `EditorView.cspNonce` facet（Task 8）。facet が効かない過去バグの報告があるため `@codemirror/view` は最新にし、Task 8 の手動確認と Task 14 の `securitypolicyviolation` 監視で実効性を担保する。万一機能しない場合のフォールバックは**編集画面限定**の `style-src 'self' 'unsafe-inline'`（判断基準: Task 8 Step 3 で violation が解消できないとき。閲覧系の CSP には決して波及させない）。
2. **nix importNpmLock × ネイティブバイナリ**: rolldown / oxlint / playwright はプラットフォーム別バイナリを optionalDependencies 等で配る。`npm install` → `direnv reload` で解決しない場合は、該当ツールを nixpkgs パッケージ（pkgs.oxlint、pkgs.playwright-driver 等）へ切り替える。
3. **409 応答に updatedVersion がない**: `page.version` を充当（Task 8）。rebase の正しさに影響しないことは core ソースで確認済み。
4. **scrapbox-parser にソース位置がない**: `raw` 連結によるオフセット再構成 + 行単位 fail-soft（Task 5）で吸収し、プロパティテストで不変条件を固定する。
5. **タイトル行の編集で commit 先 URL が失効する**（サーバはタイトルでページを解決するため）: SyncEngine の `currentTitle` 追跡（Task 4）と配線の URL 追従（Task 8）で解決する。
6. **localStorage キーとリネームの競合**: 永続キーは `knot:pending:<project>/<titleLc>` で、外部からのリネーム直後の再送は不一致になり得る。v1 では「再送は 404 で捨てられ、編集内容はエディタを開き直した時点の手元に残らない」ことを許容し、既知の制限として README に注記する（発生条件が「未確認コミットを残したままタブを閉じ、その間に他者がリネーム」と稀なため）。
